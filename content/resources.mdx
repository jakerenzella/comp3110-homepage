# Resources

These are some tools and readings we have found helpful.

## Tooling

- [Git & GitHub](https://docs.github.com/): you should be familiar from Gitlab from COMP1531.
- [Docker](https://docs.docker.com/): packaging your tools so they run everywhere.
- [FastAPI](https://fastapi.tiangolo.com/): a straightforward way to serve a model
  behind an API.
- [Hugging Face Hub](https://huggingface.co/docs/hub/datasets): git-backed hosting for
  your datasets, models, and eval sets.
- [DVC](https://dvc.org/): version control for data and models.
- [LiteLLM](https://docs.litellm.ai/): one API in front of every model provider, with
  routing, fallbacks, caching, rate limits, and per-key cost tracking.
  [OpenRouter](https://openrouter.ai/docs) instead if you would rather route across
  providers without running the gateway yourself.
- [Weights & Biases](https://wandb.ai/): experiment tracking and dashboards for
  training runs.
- [W&B Weave](https://docs.wandb.ai/weave): tracing and evaluation for LLM
  applications.
- [Unsloth](https://unsloth.ai/docs/get-started/fine-tuning-llms-guide): fine-tuning
  and RL that fits on a free Colab or Kaggle tier.
- [vLLM](https://docs.vllm.ai/): the production standard for serving a model to more
  than one user at a time from your own cluster. [Ollama](https://ollama.com/) for local
  development.

## Readings

### Core texts

- *AI Engineering: Building Applications with Foundation Models* by Chip Huyen
  (O'Reilly, 2025): prompting, RAG,
  fine-tuning, agents, dataset engineering, and the latency and cost of serving
  foundation models, free companion repo at
  [chiphuyen/aie-book](https://github.com/chiphuyen/aie-book).
- *Designing Machine Learning Systems* by Chip Huyen (O'Reilly, 2022). Chip's earlier
  book on classical ML systems, and an inspiration for parts of this course.

### Engineering practice

- [Tidy Data](https://doi.org/10.18637/jss.v059.i10) by Hadley Wickham (*Journal of
  Statistical Software* 59(10), 2014)
- [What We've Learned From A Year of Building with LLMs](https://applied-llms.org/)
- [Your AI Product Needs Evals](https://hamel.dev/blog/posts/evals/) and
  [The Ultimate AI Evals FAQ](https://hamelhusain.substack.com/p/the-ultimate-ai-evals-faq-now-new)
- [Rules of Machine Learning](https://developers.google.com/machine-learning/guides/rules-of-ml):
  Google's field guide to ML engineering. Predates LLMs but is still good.
- [The ML Test Score](https://research.google/pubs/pub46555/): a rubric for
  production-readiness.
- [Hidden Technical Debt in Machine Learning Systems](https://papers.nips.cc/paper/2015/hash/86df7dcfd896fcaf2674f757a2463eba-Abstract.html):
  why ML systems rot.

### If you are building agents

- [Building Effective Agents](https://www.anthropic.com/engineering/building-effective-agents)
  (Anthropic).
- [A Practical Guide to Building Agents](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf)
  (OpenAI): architecture, tooling, and guardrails.
